拿到一台新服务器，第一时间应该做什么？

很多人买到新 VPS 后的固定动作就两步：换源、装 Docker。但一台暴露在公网上的服务器，真正该优先处理的并不是装软件，而是安全。下面按照"应该先做什么、再做什么"的顺序，整理一份可以直接照着执行的初始化清单。核心原则只有一句：先把安全做好，再谈开发和运维。

一、安全加固：第一优先级

一台开着默认端口、允许密码登录的服务器，被扫描、爆破甚至沦为肉鸡只是时间问题。所以登录后的第一件事不是装什么，而是把门锁好。安全加固包括以下几项：

  • 创建一个普通用户并配置 sudo，日常操作不要直接用 root。
  • 修改 SSH 端口，从默认的 22 换成一个高位端口，能挡掉绝大多数自动化扫描。
  • 配置 SSH 密钥登录，然后关闭密码登录、禁止 root 直接登录。
  • 安装并配置防火墙（UFW），默认拒绝所有入站，只放行需要的端口（SSH、80、443 等）。
  • 安装 fail2ban，自动封禁反复尝试爆破的 IP。

⚠️ 关键提醒：改完 SSH 配置后不要直接断开当前连接。务必新开一个终端，用新用户、新端口先测试能连上，确认无误后再关掉旧窗口。否则一旦配错，就会把自己锁在门外。

一种更保守的做法是：防火墙先安装但暂不启动，等 SSH 端口和密钥都验证无误后，再开启防火墙、只放行 SSH 与 80/443，最后才配置 sudo 用户。思路一致，都是"先验证再上锁"。

二、换源与 Docker：按需配置

换源并不是每台机器都必须做的，只有在经常更新软件包、且默认源速度特别慢时才有意义，可视情况决定。

三、面板与一键脚本：自动化的选择

如果不想逐条手敲命令，面板和综合脚本可以把上面很多步骤自动化：

  • 1Panel：现代化的服务器面板，会顺带把 Docker 装好，内置镜像源也较实用。
  • 宝塔面板：老牌选择，图形化管理。
  • 科技 lion 脚本（bash <(curl -sL kejilion.sh)）：集成换源、Docker、安全配置、探针等功能的综合工具箱。

需要注意：用面板省事的同时，安全那一套（改端口、密钥、防火墙、fail2ban）该做的还是得做，不要因为有了面板就跳过。

四、运维与监控

服务器跑起来之后，需要随时掌握它的运行状态：

  • 安装探针 / 监控，实时查看 CPU、内存、流量、负载等指标。
  • 跑一遍性能测试脚本（bench 脚本），了解这台机器的真实配置与网络情况，到手先摸个底。

五、开发环境：根据需求配置

如果这台机器用于开发，则按需安装基础工具和语言运行时。

常用命令行工具

各语言运行时（按需选）

  • Python：uv（管理 Python 版本与依赖）、pixi（可替代 conda）
  • Rust：rustup + cargo
  • Go
  • Node.js：用 nvm 管理版本

个人配置与规范

  • 遵循 XDG 目录规范，保持家目录整洁
  • 配好 gitconfig、常用环境变量、常用函数与脚本
  • 初始化惯用的脚手架或一键脚本

TUI / AI 编程工具

  • opencode、codex 等终端里的 AI coding 工具，可按需安装。

六、可选：把后续交给 AI

配好免密登录后，剩余的初始化工作也可以交给 AI agent 完成：只需提出需求，它连上服务器后即可帮你搭好环境，省去逐条记命令、反复折腾的麻烦。喜欢全程掌控的可以手动执行一遍，图省事的则可让 AI 接管，看个人偏好。

小结：一份可照做的顺序清单

把上面的内容压缩成一条主线，新服务器到手后大致是这个顺序：

  1. 安全加固：建普通用户 + sudo → 改 SSH 端口 → 配密钥、关密码、禁 root → 装 UFW 防火墙 → 装 fail2ban。（最重要，别跳过）
  2. 基础环境：按需换源、装 Docker（或直接上 1Panel / 科技 lion 脚本一把梭）。
  3. 运维监控：装探针、跑性能测试摸底。
  4. 开发环境：按需装语言运行时、命令行工具，配好个人 dotfiles 和脚本。
  5. （可选） 把繁琐的后续步骤交给 AI agent。

"装什么软件"因人、因用途而异，但第一步永远是安全。先把锁配好，再谈别的。
